## P1 — reconstructed class

E2.1’s exact symbolic chain has `GLOBAL numpy ndarray` immediately in the
argument structure consumed by the `_reconstruct` REDUCE at offset 110. The
pinned Python compatibility shim at
`/public/home/xuyinghao/tmp/shiftvla-libero/lib/python3.12/site-packages/numpy/core/_internal.py:5-10`
defines `_reconstruct(subtype, shape, dtype)` and calls
`ndarray.__new__(subtype, shape, dtype)`. Thus the fixed class argument is the
exact `numpy.ndarray` GLOBAL, not a subclass and not an unresolved dynamic
class. This conclusion is maintained only while the fixed asset hash, GLOBAL
offsets, and pre-entry payload check remain unchanged; drift is rejected before
reducer execution.

## P2 — BUILD state

The two BUILD operations occur at offsets 184 and 43857. E2.1 identifies each
target as the current reconstruction symbol and each state as a symbolic tuple
object, preserving memo identity and opaque leaves. The pinned NumPy source
available for this audit contains no Python implementation of ndarray’s native
`__setstate__`; the relevant implementation is in the native NumPy core. The
exact tuple arity/field roles and whether the opaque final field is raw physical
storage cannot therefore be established without either native source/ABI proof
or prohibited state materialization.

Result: **UNRESOLVED**. Missing predicate belongs to E2 source semantics (exact
state schema), with native implementation provenance deferred to E3. A changed
BUILD target/state shape must be rejected before BUILD execution.

## P3/P4 — dtype and object-bearing condition

The fixed stream contains one direct `GLOBAL numpy dtype` and one REDUCE at
offset 152 whose callable is that symbol. The argument tuple is structurally
known by the E2.1 VM, but its descriptor leaves are physical/opaque. NumPy’s
Python `_internal.py` only forwards dtype behavior into the native `_core`
implementation; no safe source-only predicate here proves the exact descriptor
branch or `hasobject` result. In particular, absence of a Python object GLOBAL
does not prove a non-object dtype: object-bearing status can be encoded in dtype
metadata and native descriptor state.

Results: **dtype descriptor semantics UNRESOLVED** and **object-bearing dtype
UNRESOLVED**. The missing predicates are E2 source/native semantic conditions;
they are not silently reclassified as E3 merely to obtain PASS.

## P5 — dynamic authority

For the fixed bytes, callable and class authority is closed structurally:

- reducer callables originate only from the four direct GLOBAL records;
- `_reconstruct` receives the direct `numpy ndarray` symbol;
- dtype construction receives the direct `numpy dtype` symbol;
- BUILD targets are the exact prior symbolic reconstruction objects;
- no `STACK_GLOBAL`, extension opcode, NEWOBJ, persistent ID, or indirect
  GLOBAL exists in the fixed stream.

This excludes reducer/class substitution in the fixed payload. It does not
grant native semantic safety to those callables; any changed bytes or unresolved
symbol causes pre-entry rejection.

## P6 — validation/use consistency

Classification: **CROSS_PACKAGE_DEPENDENCY_ON_FUTURE_ADMISSION**. E1 evidence
binds the current asset bytes, ZIP members, and official call site. It does not
prove that a future loader executes the same bytes without substitution, nor
bind the native NumPy implementation/build. Those checks belong to the future
E1/E5 admission contract. No future implementation promise is counted as
current E2 evidence.
